# AI SEO Article Factory — фабрика SEO-статей на автозадачах Claude Code + Kimi

Рабочая система, которая каждый день без человека пишет, публикует, обновляет и усиливает статьи блога — и отчитывается о результатах. Крутится в проде на [skillmake.ru](https://skillmake.ru): 130+ статей за три недели, рост показов в Яндексе с ~400 до ~1400/день и топ-10 по 376 запросам за первые две недели после старта индексации.

Здесь выложены **реальные промты, брифы и скрипты** этой фабрики — не учебный пример, а то, что работает прямо сейчас. Разбор всей системы — в статье [«Контент-завод на ИИ»](https://skillmake.ru/articles/kontent-zavod-na-ii) блога skillmake.

*(EN: a production pipeline of scheduled Claude Code tasks + Kimi CLI that writes, publishes, refreshes and boosts SEO articles daily. Prompts and scripts are in Russian — that's the point: it ranks in Yandex.)*

## Как устроен день фабрики

```
08:06  Отчёт        Kimi собирает свод: Вебмастер, GSC, Метрика, воронка, поддержка
09:08  Усиление     одна статья-победитель: исследование → правки → noindex-превью → ОК владельца
09:31  Конвейер     5 новых статей: Вордстат-валидация тем → Kimi пишет → приёмка
10:40  Ротация      10 самых старых статей: Kimi проверяет факты живьём → точечные правки
15:07  Финализатор  ОДИН деплой всего дня: сборка → коммит → выкат → проверка → переобход
```

Роли: **Kimi Code CLI** делает тяжёлую генерацию и проверку (дёшево), **Claude Code** ставит задачи, принимает результат, отвечает за деплой и не даёт系统е соврать. Человек нужен в двух точках: утвердить «было/стало» перед выкатом усиленной статьи и залогиниться там, где нужны живые скриншоты.

## Состав репозитория

| Папка | Что внутри |
|---|---|
| `prompts/` | Пять регламентов автозадач — дословные рабочие промты (отчёт, усиление, конвейер, ротация, финализатор) |
| `briefs/` | Брифы для Kimi: написание статьи, актуализация, ежедневный отчёт |
| `scripts/` | `build-site.mjs` — генератор (md → html: оглавление, якоря, mermaid, related, FAQPage JSON-LD); `ai-tells-scan.mjs` — детектор ИИ-маркеров текста; `gen-covers-auto.py` — обложки; `wm-recrawl.ps1` — переобход Яндекс.Вебмастера |
| `docs/` | Правила де-ИИзации текста, правила публикации статьи, чек-листы усиления, форматы журналов и очереди деплоя |

## Ключевые принципы (выстраданы, не придуманы)

1. **«Статья актуальна» — нормальный результат.** Без этого правила в брифе LLM выдумывает правки ради отчёта.
2. **Факты проверяются живьём** (curl к API/докам), не по памяти модели. Так нашлась отключённая модель в топ-статье: код из неё возвращал 400 всем читателям.
3. **Правки ранжирующихся статей — только аддитивные** (добавить/переставить/исправить факт). Рискованные правки (title/H1) — с базой «до», контролем позиции через 7 дней и автооткатом.
4. **Один деплой в день вместо четырёх.** Дневные задачи пишут файлы и запись в очередь; финализатор выкатывает всё одним циклом — экономия ~15–20К токенов/день на обвязке.
5. **Де-ИИзация обязательна** — машинный текст понижается и поисковиками, и читателями. Детектор — в `scripts/ai-tells-scan.mjs`.
6. **Каждая проверка — отдельным запросом.** Статус страницы 200 ничего не говорит о картинках внутри неё.

## Что отправляется в Яндекс

- **Переобход** изменённых URL — API Вебмастера (`wm-recrawl.ps1`), квота 150/день бережётся: «проверено, правок нет» не переобходится.
- **Sitemap** — регенерируется при каждой сборке, в Google переотправляется через Search Console API.
- **FAQPage JSON-LD** — строится генератором из раздела «Частые вопросы» каждой статьи (поэтому раздел запрещено переименовывать).
- Обратная связь: позиции и CTR из Вебмастера + поведение из Метрики ежедневно попадают в отчёт 08:06 и триггерят усиление в 09:08.

## Адаптация под себя

Промты самодостаточны, но привязаны к структуре проекта (`course/articles/*.md` → генератор → Next.js). Плейсхолдеры вида `<workspace>`, `<METRIKA_ID>`, `<VENDOR_NUMBER>` замените своими значениями. Деплой в примерах идёт через обёртку с файловым локом и антирегрессией (несколько сессий на одном клоне) — замените своим процессом.
