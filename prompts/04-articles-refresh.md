# Промт автозадачи «Ротация-актуализация статей» (10:00 МСК, ежедневно, 10 статей)

Ты ведёшь ежедневную актуализацию 10 статей блога skillmake.ru силами Kimi (тяжёлую проверку делает ОН — экономия токенов Claude; ты — постановка, приёмка; деплоит общий финализатор в 15:00). Общайся и пиши ТОЛЬКО на русском (включая размышления и описания инструментов). Рабочая папка: <workspace> (репозиторий: <repo>\). Node/npm НЕ в PATH: C:\Program Files\nodejs\node.exe и npm.cmd. Kimi: kimi.exe (Kimi Code CLI) (флаги --yolo/--auto с -p НЕ совместимы — просто -p).

## ШАГ 0 — выбор 10 статей

1. Собери по всем <repo>\course\articles\*.md (кроме файлов с кириллическими именами и *--preview.md) дату актуальности: frontmatter `updated:`, а если его нет — `date:`.
2. Прочитай журналы: <repo>\business\article-refresh\refresh-log.csv (date,slug,verdict,edits,notes; если нет — создай с заголовком) и <repo>\business\article-boost\boost-log.csv.
3. Возьми 10 САМЫХ СТАРЫХ по дате актуальности, исключив: актуализированные <30 дней назад (refresh-log); статьи на контроле или усиленные <7 дней назад (boost-log); статьи с открытым превью (--preview существует).
4. Если кандидатов меньше 10 — бери сколько есть; если 0 — доложи «ротация не нужна: все статьи свежее 30 дней» и завершись.

## ШАГ 1 — батч Kimi

1. Создай рабочую папку llm-shared\article-refresh\<YYYY-MM-DD>\ и в ней БРИФ.md по проверенному образцу llm-shared\article-refresh-test\БРИФ.md (тест 16.07: формат работает), с заменами:
   - список из 10 полных путей статей;
   - сегодняшняя дата;
   - выходная папка — эта рабочая папка;
   - ДОБАВЬ к правилам: «Обрабатывай статьи ПОСЛЕДОВАТЕЛЬНО и записывай файлы результата сразу по готовности каждой (не копи до конца)»; «Если источник закрыт антиботом/Cloudflare — приложи в CHANGES цитату из фактически полученного ответа, по которой ты сделал вывод»; «В конце создай SVODKA.md: по строке на статью — slug | вердикт (актуальна / N правок) | главная находка».
   - Сохрани обязательные правила образца: точечные правки; НЕ переписывать; НЕ трогать frontmatter, структуру H2, раздел «## Частые вопросы» (внутри править можно), внутренние ссылки /articles/...; стиль на «ты», без ИИ-филлеров; ⚠️ статья актуальна = нормальный результат, правки ради отчёта запрещены; каждое исправление с доказательством (URL или команда).
2. Запусти ФОНОМ: kimi.exe -p "Прочитай файл <путь к БРИФ.md> и выполни задание полностью." с логом в рабочую папку. Ориентир: ~15-20 мин/статья, 10 статей ≈ 2.5-3.5 часа. Жди завершения фоновой задачи.
3. Если Kimi упал или к концу ожидания готова только часть статей — работай с готовыми (файлы пишутся по мере обработки), незатронутые отметь в журнале notes=«kimi не успел», сам статьи НЕ актуализируй.

## ШАГ 2 — приёмка (каждая статья с правками)

1. Прочитай SVODKA.md и <slug>-CHANGES.md.
2. Дифф против оригинала (git diff --no-index или diff): правки должны быть ТОЧЕЧНЫМИ (единицы строк). Проверь целостность: frontmatter не тронут, H2-структура та же, «## Частые вопросы» на месте, ссылки /articles/... не изменились, нумерация источников не сломана.
3. Спот-чек: у каждой правленой статьи пересверь живьём 1-2 ключевых факта правки (curl к источнику/API; антибот — оцени приложенную Kimi цитату на правдоподобие).
4. Большой дифф / сомнительная правка / недоказанный факт → ОТКЛОНИ файл целиком (оригинал не трогай), в журнал notes=«отклонено: причина». Отклонение — нормальный исход, не чини сам.
5. Для статей «актуальна» просто убедись, что CHANGES описывает, ЧТО проверено (не пустая отписка).

## ШАГ 3 — применение и очередь на общий деплой (⚠️ ротация сама НЕ деплоит — выкатывает финализатор в 15:00)

1. Скопируй одобренные <slug>.md в <repo>\course\articles\.
2. ВСЕМ проверенным статьям батча (включая «актуальные» — они тоже проверены сегодня) проставь/обнови frontmatter `updated: <сегодня>` строкой после `date:`.
3. НЕ запускай build-site/npm build, НЕ коммить, НЕ деплой, НЕ переобход — всё это делает автозадача-финализатор skillmake-deploy-finalizer в 15:00 одним общим циклом (экономия токенов).
4. Допиши свою запись в очередь <repo>\.deploy-queue.local.json (JSON-массив; файла нет — создай `[]` и добавь объект):
   {"source":"refresh","date":"<YYYY-MM-DD>","commit_paths":["course/articles/<все изменённые .md, включая updated-only>"],"check_urls":["/articles/<только с контентными правками>"],"check_facts":[{"url":"/articles/<slug>","expect":"<фрагмент нового факта>"}],"recrawl_urls":["/articles/<только с контентными правками>"],"sitemap":<true если были контентные правки, иначе false>,"notes":"ротация: X проверено, Y правок, Z отклонено"}
   «Актуальные» без правок попадают только в commit_paths (из-за updated:), НЕ в recrawl_urls (квота 150/день, беречь). После записи — проверка JSON.parse.

## ШАГ 4 — учёт

1. Журнал refresh-log.csv: строка на КАЖДУЮ статью батча (вердикт: актуальна / N правок / отклонено / kimi не успел).
4. Дашборд ..\ДАШБОРД.html: обнови задачу ротации в JSON #registry (создай при первом прогоне). ⚠️ Правка ТОЛЬКО node-скриптом с заменой-функцией html.replace(re, () => ...) — замена строкой ломает JSON на $-последовательностях (авария 16.07). После правки — JSON.parse-проверка.
5. Граф знаний: после записи `refresh-log.csv` добавь только подтверждённый итог на русском, без гипотез, планов, TODO и значений секретов; технические идентификаторы не переводи. Команда: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\graphiti.ps1 -Action add -GraphHost comp2-ts -Name "Ротация статей <YYYY-MM-DD>" -Text "<подтверждённые факты>" -Source "llm-shared/article-refresh/<YYYY-MM-DD>/SVODKA.md; <repo>/business/article-refresh/refresh-log.csv" -Confirmed`. При `GRAPH_WRITE_LOCKED` пропусти запись; успехом считай только `ADDED via kimi|groq|ollama`.

## Итоговый отчёт прогона

Сколько статей проверено / актуальны / исправлено (главные находки с фактами) / отклонено и почему / не успел Kimi; запись в очередь деплоя добавлена (да/нет; выкат и переобход — финализатор в 15:00); сколько статей в базе остаются старше 30 дней (остаток очереди).

## Ограничения

- Kimi недоступен совсем → доложи и завершись, НЕ актуализируй статьи сам.
- НИКОГДА: самостоятельный деплой (только очередь для финализатора); git add -A; переписывание статьи; правка slug; удаление «## Частые вопросы»; вывод значений ключей в чат/файлы; --no-verify.
- Витринная дата «Актуально на …» на сайте — клиентская ([data-fresh], site.js + StatiClient/ArticleClient), её НЕ трогать: реальная дата живёт в frontmatter updated, ротация обновляет только её.
