# Правила публикации новой статьи (SEO + общие) — ОБЯЗАТЕЛЬНЫ для каждой статьи

_Введены 2026-07-03 по итогам SEO-аудита (business/seo/*). Пишет человек или Kimi — правила одни. Файл служебный: генератор статей игнорирует md-файлы с кириллическим именем (фильтр в build-site.mjs)._

## 1. Frontmatter (строго)

```
---
title: <до 65 символов, с поисковой фразой ближе к началу; H1 = title>
seoTitle: <опционально: если title длиннее — короткая форма для <title>>
excerpt: <до 160 символов, 1-2 предложения с фразой; идёт в description и карточку>
tag: Объяснялка | Практика | Бизнес
date: <YYYY-MM-DD — реальная дата публикации>
read: <N мин (~150 слов/мин)>
related: <опционально: 2-3 слага родственных статей; иначе подберётся автоматически>
---
```

- Поисковую фразу проверяй Вордстатом (скилл .claude/skills/yandex-wordstat, тело `{phrase,numPhrases:"строка",folderId}`); частота <100/мес — подумай о другой формулировке.
- Слаг: латиница-дефисы, короткий, с ключом (`chto-takoe-api`), навсегда (не переименовывать).

## 2. Структура текста

- Интро 2-4 предложения с проблемой читателя. Без «в этой статье мы рассмотрим».
- H2 = подвопросы темы (каждый H2 — потенциальный запрос; «что такое X», «как настроить X»). H3 — по необходимости. Пропусков уровней нет.
- 800–1500 слов, **строго на «ты»** (не «вы»!) — единый бренд-голос по всему блогу; термины поясняются при первом употреблении. ⚠️ Часть старых статей написана на «вы» (см. ниже, ждут ручной переработки) — новые пиши только на «ты».
- Обязательные блоки: **FAQ** (3-5 вопросов `### Вопрос?` в конце — кандидат на расширенный сниппет) и **Источники** (для фактологических статей: `Название: URL` — генератор сам сделает читаемый анкор).
- 2-4 внутренние ссылки на родственные статьи ИЗ ТЕКСТА (не только related-блок) + 1 естественная ссылка на /kurs, где уместно.
- Один-два дисклеймера максимум, не после каждого раздела.

## 3. Запрещено (юр + качество)

- Обещания дохода/«гарантированно заработаешь»/«пассивный доход»; «опубликовано в App Store» (только «отправлено»).
- Выдуманные цены/шаги интерфейсов сторонних сервисов — только «актуальные тарифы на сайте сервиса».
- Голые URL в тексте, ссылки на localhost, ссылки на несуществующие статьи, реф-ссылки без rel="sponsored".
- Каннибализация: перед новой темой проверь `course/articles/` — нет ли статьи под тот же запрос. Есть похожая → расширяй её или явно разводи интенты (простая/глубокая) с перелинковкой.

## 4. Публикация (конвейер)

1. Файл в `course/articles/<slug>.md`.
2. Обложка: `python scripts/gen-covers-auto.py` — построит фирменную svg из frontmatter для всех статей без обложки (ручной словарь нужен только если авто-вариант некрасив — тогда gen-covers-batch*.py).
3. `node scripts/gen-og-covers.mjs` — png-версия обложки для og:image/JSON-LD.
4. `node scripts/build-site.mjs` — генерит HTML статьи в **content/articles/** (с 13.07 статьи рендерит Next-роут /articles/[slug]; обложки по-прежнему в public/articles/img) (авто: canonical, og, Article JSON-LD, дата по-русски, автор-блок, related, CTA, анкоры источников), обновляет public/stati*.html (их читает Next-хаб) и sitemap.xml.
5. `node scripts/check-articles.mjs` — QA-скан; чинить до нуля проблем.
6. Секрет-скан → коммит (md + content/articles/*.html + img + public/stati* + sitemap) → deploy-amvera (build пересоберёт SSG-страницы; мгновенная публикация без деплоя — POST /api/revalidate с Bearer REVALIDATE_TOKEN, когда env заведён).
7. После деплоя: переобход в Вебмастере (API recrawl новых URL; квота ~150/сутки).
8. Если статья упоминается в модуле курса — вернуть ссылку в секцию «📚 Хочу понять» соответствующего module-N.md → `node scripts/build-reader.mjs` → пересборка Next → тот же деплой.

## 5. Чек-лист приёмки (быстрый)

- [ ] title ≤65, excerpt ≤160, tag/date/read корректны
- [ ] H1 один (из frontmatter), H2-структура без пропусков
- [ ] FAQ есть; источники с названиями; 2+ внутренние ссылки
- [ ] юр-фильтр пройден (доход/гарантии/App Store)
- [ ] обложка svg+og-png на месте, статья в /stati и sitemap
- [ ] check-articles: 0 проблем
