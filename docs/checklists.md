# Чек-листы усиления статьи (используются автозадачей article-boost)

Два списка вопросов, на которые отвечает исследование ПЕРЕД правками ранжирующейся статьи. Заполняются числами из Вебмастера/Метрики/выдачи, не мнениями.

## Глазами клиента (7 вопросов)

1. **Что он хочет по каждому запросу?** Интент: сделать сейчас / понять / сравнить.
2. **Получает ли сразу?** На каком проценте статьи начинается ответ, сколько мобильных экранов до него.
3. **Есть ли навигация?** Оглавление, якоря на разделы.
4. **Верит ли статье?** Работает ли код при копировании, свежи ли факты (проверять живьём по API/докам!), есть ли реальные скриншоты, дата.
5. **Совпадает ли сниппет с первым экраном?** Title/description обещают то же, что видно при приземлении.
6. **Может ли быстро действовать?** Точные URL и названия кнопок, готовые команды, короткий путь.
7. **Что делать после ответа?** Следующий шаг (смежная статья, продукт) в момент успеха — или читатель просто уходит.

## С нашей стороны (10 вопросов)

1. **Есть ли триггер оптимизации?** Просадка позиции / рост показов без кликов / устаревшие факты — подтверждено числом.
2. **Структура под интент:** порядок разделов отвечает главному запросу?
3. **Какие ключи расширить?** Запросы с показами, слов из которых нет в тексте (Вебмастер) + смежные (Вордстат).
4. **Перелинковка:** сколько статей ссылаются НА эту (минимум 3–5 входящих), куда ведёт она.
5. **Чем бьём конкурентов?** Что есть у топ-3, чего нет у нас — и наоборот (наш уникальный опыт/замеры).
6. **Каннибализация:** не конкурируют ли наши другие статьи за тот же запрос.
7. **Разметка:** FAQPage есть? HowTo уместен?
8. **Что из правок рискованно?** Title/H1 ранжирующейся страницы — отдельным пунктом, с планом отката.
9. **Как поймём, что сработало?** База «до» (позиции, CTR, время, глубина, цели) → контрольная точка через 7 дней.
10. **Считаем ли результат вообще?** Целевые кнопки размечены событиями аналитики?

## Правило аддитивности

Правки ранжирующейся статьи — только добавить / переставить / исправить факт / закрыть дыру. Переписывание с нуля запрещено: агрессивная переработка роняет позиции. Раздел FAQ не переименовывать (из него строится FAQPage JSON-LD).
