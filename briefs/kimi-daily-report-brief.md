# Ежедневный свод-отчёт skillmake.ru (SEO + трафик + продукт)

Ты — аналитик. Собери отчёт по сайту skillmake.ru: детально ЗА ВЧЕРА + НАКОПИТЕЛЬНЫЙ СВОД с начала (динамика по дням). Работай из папки `<workspace>`. Пиши ТОЛЬКО на русском. Не выдумывай числа — только то, что вернули команды; если данных нет, так и пиши «нет данных / лаг».

## 0. Файл-история (НАКОПИТЕЛЬНЫЙ СВОД) — читать И дополнять
Есть постоянный файл `llm-shared/seo-daily-history.csv` (колонки: date,wm_shows,wm_clicks,wm_avg_pos,wm_top10,visits_total,visits_organic,regs,paid_succeeded) — накопленная история по дням.
1. **В начале** прочитай его — это основа накопительного свода.
2. **После сбора вчерашних чисел** (разделы 1–4) — ДОПИШИ/ОБНОВИ строку за вчерашнюю дату (не дублируй: если строка с этой датой уже есть — обнови её значениями; иначе добавь новую в конец). Пустые ячейки, где данных нет (лаг Вебмастера) — оставляй пустыми, дозаполнишь в следующие дни, когда лаг пройдёт (проверь и обнови также строки за 1–2 предыдущих дня, если по ним появились данные Вебмастера).
3. Файл — источник для раздела «Накопительный свод»: полная таблица по дням + суммарные показы/клики/регистрации/оплаты за весь период + тренд (плато→рост, где перелом).

## Какие данные собрать (и точные команды)

### 1. Яндекс.Вебмастер — SEO-видимость
Рабочая папка скилла: `.claude/skills/yandex-webmaster`. Команда (подставь дату):
```
bash scripts/popular_queries.sh --host skillmake.ru --order-by TOTAL_SHOWS --date-from <YYYY-MM-DD> --date-to <YYYY-MM-DD> --limit 500 --no-cache
```
Результат кэшируется в `cache/host_https_skillmake.ru_443/queries/popular_*.tsv` (свежайший файл по mtime; колонки: query_id, query_text, shows, clicks, avg_show_pos, avg_click_pos).
- Посчитай за вчера: запросов, показов, кликов, средневзвешенная позиция (sum(pos*shows)/sum(shows)), сколько запросов в топ-10.
- ⚠️ У Вебмастера лаг 1–2 дня: если за вчера пусто — возьми последний день с данными и явно пометь дату.
- Дай топ-5 запросов по кликам и топ-5 по показам (текст, показы, клики, позиция).
- Сравни с предыдущим днём (запроси и его): показы/клики/топ-10 — рост или падение, в %.

### 5. Поддержка — обращения и НЕОТВЕЧЕННЫЕ (два канала)

**5.1. Чат-виджет на сайте** (таблицы `support_conversations` + `support_messages`; `direction`: `in`=посетитель, `out`=мы). ⚠️ Живой ответ оператора = строка `out` с НЕПУСТЫМ `tg_message_id` (оператор отвечает из Telegram). Строка `out` с `author_name='skillmake'` и пустым `tg_message_id` — это АВТО-ОТВЕТ, ответом НЕ считается.
Запрос (через тот же `<sql-endpoint>`, секрет — см. п.4):
```sql
select c.id, c.page, c.contact, c.status, c.created_at, c.last_message_at,
  (select count(*) from support_messages m where m.conversation_id=c.id and m.direction='in') as in_cnt,
  (select max(created_at) from support_messages m where m.conversation_id=c.id and m.direction='in') as last_in,
  (select max(created_at) from support_messages m where m.conversation_id=c.id and m.direction='out' and m.tg_message_id is not null) as last_operator_reply
from support_conversations c order by c.last_message_at desc limit 30
```
**НЕОТВЕЧЕННОЕ** = `last_operator_reply IS NULL` ИЛИ `last_in > last_operator_reply`. Для каждого неотвеченного покажи: сколько висит (часы от `last_in`), страницу, контакт, и ПЕРВЫЕ 150 символов текста (добери из `support_messages` по `conversation_id`, `direction='in'`). ⚠️ Текст обращения цитируй ДОСЛОВНО из поля `body` (не пересказывай, не подменяй техническими id вроде visitor_key).
⚠️ **ОТСЕЙ тестовые/свои** — НЕ считай реальными обращения, где текст похож на тест (`тест`, `проба`, `/support_here`, `test`) ИЛИ `author_name` = наш собственный адрес (`<ВАШ_EMAIL_1>`, `<ВАШ_EMAIL_2>`, `@skillmake.ru`). Их выводи отдельной строкой «тестовые: N (игнор)».

**5.2. Почта <SUPPORT_EMAIL>** (IMAP). Пароль — в `<файл секретов вне git>` строка вида `<SUPPORT_EMAIL> — пароль: <значение>` (НЕ печатать!). Python:
```python
import imaplib
M=imaplib.IMAP4_SSL('imap.timeweb.ru',993); M.login('<SUPPORT_EMAIL>', PW); M.select('INBOX')
# всего / непрочитанных / за сутки:
M.search(None,'ALL'); M.search(None,'UNSEEN'); M.search(None,'(SINCE "<DD-Mon-YYYY>")')
```
Дай: всего писем, **непрочитанных**, пришло за сутки; по непрочитанным/новым — From + Subject (декодируй MIME-заголовки через `email.header.decode_header`).
⚠️ **Помечай спам** (типичное: партнёрские предложения от незнакомых доменов, «Rechnung», «partnership», нигерийские схемы) и наши системные письма (From: skillmake / <SUPPORT_EMAIL>) — они НЕ клиентские обращения. Реальным клиентским письмом считать только адресованное по делу от живого человека.

**Итог по поддержке для отчёта:** «Реально неотвеченных: N» (виджет + почта), с перечнем и временем ожидания. Если 0 — так и пиши «неотвеченных нет».

## Формат отчёта
Сохрани в файл `llm-shared/daily-report-<YYYY-MM-DD>.md` И выведи целиком в ответ.

⚠️ **ГЛАВНОЕ ПРАВИЛО СТРУКТУРЫ: сначала ВЫВОДЫ, потом данные.** Человек читает первые 20 строк — там должно быть всё, ради чего отчёт. Детальные таблицы — ниже, как доказательная база.

### ЧАСТЬ A — ВЕРХ (выводы и действия). Порядок строго такой:
1. **Заголовок**: `# Свод skillmake.ru — <дата>` + одна строка «данные: Вебмастер за X (лаг), Метрика за Y, …».
2. **🚨 ТРЕБУЕТ ДЕЙСТВИЯ** — СТРОГО только то, где реально нужен человек прямо сейчас:
   - реально неотвеченные обращения (виджет/почта) — сколько висят и о чём;
   - сбой: упавшая оплата (`payment_failed`>0 или order со статусом canceled/pending), сломанная цель (была >0, стала 0), недоступность сайта;
   - аномалия: обвал трафика/показов >40% к предыдущему дню, всплеск фейк-регистраций/ботов.
   ⚠️ НЕ пиши сюда рутину: неподтверждённая почта, отсутствие оплат при нулевом трафике, обычные колебания ±20%, тестовые сообщения. Если ничего из списка выше нет — ровно одна строка: «Действий не требуется».
3. **📊 ГЛАВНЫЕ ЦИФРЫ ЗА ДЕНЬ** — компактный блок 5–8 строк: показы/клики Яндекс (с Δ% ко вчера), визиты (в т.ч. органика), регистрации, оплаты, установки iOS, неотвеченные. Формат «метрика: значение (Δ)».
4. **🧠 ВЫВОДЫ** — 3–5 пунктов по сути: что выросло/упало и почему (в контексте всей истории, не только вчера), лучшая статья дня, узкое место воронки. Каждый пункт — с цифрой-опорой. Если вчера усиливалась статья (раздел 6) — обязательный пункт: как она отреагировала (позиция/CTR/поведение против базы «до»).
5. **🎯 РЕКОМЕНДАЦИЯ** — 1 (максимум 2) конкретных действия на сегодня, с обоснованием цифрой.

### ЧАСТЬ B — НИЗ (детальные данные, как доказательство). Порядок:
6. **SEO Яндекс** — таблица вчера vs позавчера с Δ%; топ-5 запросов по кликам; топ-5 по показам (если списки сильно пересекаются — второй давай без повторов).
7. **Google Search Console** — строка состояния/цифры.
8. **Трафик и поведение** — таблица по источникам; лучшие статьи (визиты + время); органика: время/отказы/глубина. Подозрительно длинные internal/ad-сессии помечай «вероятно, собственный трафик».
9. **Воронка** — открытия статей → kurs_click → переход к оплате → оплат; регистрации (кол-во + каналы + фейки); попытки оплат со статусами.
10. **🎧 Поддержка (детали)** — виджет: всего/новых/неотвеченных с текстом; почта support@: всего/непрочитанных/новых (спам и системные — отдельно).
10b. **🔧 Усиление статей** (только если в журнале есть строка за вчера или статьи на контроле) — таблица: статья | правки (кратко из changes) | база «до» (позиция/CTR/kurs_click) | сейчас | дней из 7. Отдельной строкой — риск-правки (risk_edits) и дата контрольного решения.
11. **📈 Накопительный свод (с начала)** — полная таблица по дням из файла-истории + строка ИТОГО + краткий тренд (где перелом, во сколько раз вырос).

Стиль: сухие цифры и таблицы, без воды. Числа не округляй до потери смысла. Если какая-то команда упала — повтори 1 раз, затем зафиксируй сбой в отчёте и продолжай остальное.
